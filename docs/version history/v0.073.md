# v0.073 -- Project Knowledge: Git provider

**Status: PLANNED -- not yet started.** Forward-looking summary,
written ahead of implementation as part of staging
[`docs/Implementation/PROJECT-KNOWLEDGE-ADDENDUM.md`](../Implementation/PROJECT-KNOWLEDGE-ADDENDUM.md)
(stage 3 of 8). Will be updated to reflect actual shipped behavior
once this stage lands.

Third rung -- Git as the first concrete Project Knowledge provider,
read-only.

## What's planned

- Detect whether `.git/` exists.
- Read repository identity, current revision, and branch/ref.
- Read working-tree state: clean or dirty, shallow-clone state.
- Gracefully report unavailable Git state when `.git/` doesn't exist
  -- Git is a knowledge source when present, never a requirement.

This stage never writes to `.git/` and never writes to `.arklight/`
either -- it's purely "can the compiler read Git metadata," with
persistence deferred to `v0.074`. ARKlight does not become a VCS: no
commits, branches, tags, merges, or rebases are created or touched.
