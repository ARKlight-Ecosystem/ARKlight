First rung of the Project Knowledge ladder -- the directory itself,
with nothing yet depending on it.

## What shipped

- `arklight/knowledge/` (new package): `KnowledgeStore(project_root)`,
  the one object that owns a project's `.arklight/` directory. It is
  compiler infrastructure, not authoring vocabulary, so it is imported
  as `arklight.knowledge` and is not exported from `arklight`.
  - `ensure()` -- detect-or-create `.arklight/` and write its format
    marker, `PROJECT`, containing `knowledge_format=1` (proposal §17).
    It only ever creates; an existing directory with an older, newer
    or unreadable marker is left exactly as found and reported.
  - `status()` -- classify the directory as `ABSENT`, `UNMARKED`,
    `CURRENT`, `OUTDATED`, `INCOMPATIBLE`, `CORRUPT` or `UNUSABLE`
    (the proposal's "current / outdated / incompatible / safely
    regeneratable"). Read-only.
  - `read(name)` / `write(name, facts)` -- safe helpers later stages
    build on. `name` may be nested (`"KNOWLEDGE/COMPONENTS"`, the
    proposal's own layout). `write()` creates the directory on demand
    and replaces the file atomically.
- Plain text only: UTF-8, one `key=value` per line, `#` comments, no
  database. Open `.arklight/` in any editor and read it.

```text
.arklight/PROJECT

# ARKlight Project Knowledge -- derived by the compiler, safe to delete.
# Deleting this directory never changes what the project builds.
knowledge_format=1
```

## Deliberate limits

- **Nothing in the compiler uses it yet.** A build does not create,
  read or depend on `.arklight/`; the same source produces
  byte-identical output with the directory absent, populated, or
  corrupt. Deleting it is a pure no-op (proposal §2, §14, §21.3).
  `tests/test_project_knowledge_v0071.py` pins this, and fails the day
  another module imports `arklight.knowledge` so that change is made
  deliberately (it is `v0.072`'s to make).
- **Treated as untrusted input.** A cloned repository can ship its own
  `.arklight/`. The directory, and every file and subdirectory under
  it, must be real -- a symlink is refused rather than followed, so
  a hostile checkout cannot aim the compiler's writes elsewhere. File
  names are validated so they can only resolve inside the directory,
  a file over 1 MiB is refused, and nothing is written into a
  directory whose format is not the current one.
- **Failures are non-fatal by contract.** Anything wrong with the
  directory raises a `KnowledgeError`, which later stages are to treat
  as "carry on without persistent knowledge". A caller's own mistakes
  (a bad name, a non-string value) raise plain `ValueError`/
  `TypeError` instead, so catching `KnowledgeError` cannot hide a bug.
- **Not decided here.** Whether ARKlight adds `.arklight/` to a
  project's `.gitignore`, and whether the directory is created on
  every build or only when a feature needs it, are proposal §20 open
  questions; stage 1 does neither, and `write()` creating it lazily
  is a helper behavior, not that decision.
- **No Git, providers, facts model or build history.** Those are
  `v0.072`-`v0.077`.
