Fourth rung -- writing what the Git provider can read into
`.arklight/`, so it outlives `.git/` itself.

## What's planned

- Persist derived Git facts (revision, branch, dirty state, and
  similar) into `.arklight/`.
- Preserve that knowledge once `.git/` is later unavailable -- the
  worked case this stage targets: `git clone` followed by
  `arklight build` populates `.arklight/`; a later `rm -rf .git` (or
  unzipping a plain source archive) does not erase what ARKlight
  already learned.
- Avoid copying repository internals -- store derived facts like
  `last_successful_revision`, not Git objects, and keep remote-URL
  information out by default (it can carry private hostnames or
  other sensitive detail).

`.arklight/` stays derived state, not a replacement for Git: it
remembers what ARKlight observed, not the repository ARKlight
observed it from.
