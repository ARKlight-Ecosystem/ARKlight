# v0.063 -- JS vocabulary: small new runtime primitives

Third rung of the JS vocabulary expansion (see
[`docs/Implementation/JS-VOCABULARY-ADDENDUM-v0.070.md`](../Implementation/JS-VOCABULARY-ADDENDUM-v0.070.md)
stage 3 of 10) -- five small runtime primitives, each extending
`arklight/backend/js/runtime/*.py` without a new IR node.

## What shipped

- `Action.geolocate(name)` -- a one-shot, argument-less action.
  `navigator.geolocation.getCurrentPosition` writes a plain
  `{lat, lng}` object into `State(name)` once the browser's own
  permission prompt resolves. Asynchronous, unlike every other
  action: the write happens some time after the click returns, not
  before -- safe because the dispatcher already calls `action(store,
  key, args)` and moves on without waiting for a return value.
  Missing browser support, an insecure context, or a denied
  permission all degrade to "the state just never updates," never a
  thrown error.
- Clipboard **paste** behavior (`on_click="paste"`) --
  `navigator.clipboard.readText()` into the `behavior_target`
  selector's `.value` (an `Input`/`Textarea`, also dispatching a real
  `input` event so a `bind_value=Bind.model(...)` binding on the same
  element picks the pasted text up too) or `.textContent` otherwise.
  Mirrors `copy.py` closely -- same selector, same clipboard-
  availability guard, just reading instead of writing.
- `matchMedia`-driven boolean state
  (`State(name, initial, media="(min-width: 768px)")`) -- as soon as
  the runtime initializes, `initial`'s server-rendered guess is
  overridden with `window.matchMedia(media).matches`, and one
  `MediaQueryList` "change" listener per declared media state keeps
  writing `State(name)` as the viewport crosses the query's
  breakpoint.
- `reveal`/`lazy` behavior via `IntersectionObserver`
  (`on_reveal="reveal"`) -- unlike every other named behavior, never
  click-triggered, so it lives on its own prop (`on_reveal=`, not
  `on_click=`) and its own small registry
  (`arklight.ir.schema.REVEAL_REGISTRY`), wired from a dedicated
  mount-time pass (`wireReveal`, re-run after every `app_shell`
  boosted swap) rather than the click interceptor. Adds
  `toggle_class` (default `"is-visible"`, the same attribute/default
  `toggle`/`dismiss` already use) to the element itself the first
  time it enters the viewport, then stops observing it -- a one-shot
  scroll-reveal.
- Debounced/throttled two-way binding -- `Bind.model(name,
  debounce=300)`/`Bind.model(name, throttle=300)` extend `bind_value=`
  to accept the existing `MODIFIER_REGISTRY` `debounce:<ms>`/
  `throttle:<ms>` tokens (the same ones
  `Action.*(...).debounce(...)`/`.throttle(...)` already validate),
  wiring the modifier plumbing that already existed for actions into
  `wireModelBinding` too. `Bind.model(name)` with neither modifier
  keeps returning a plain string -- every existing call site is
  unaffected.

```python
State("here", None)
Button("Find me", on_click=Action.geolocate("here"))

Button("Paste", on_click="paste", behavior_target="#search")
Input(id="search")

State("is_wide", False, media="(min-width: 768px)")
Show(Predicate.truthy("is_wide"), Text("Desktop layout"))

Container(on_reveal="reveal", toggle_class="fade-in")

Input(bind_value=Bind.model("query", debounce=300))
```

Also fixed in this stage, found while making sure `from arklight
import *` reached this stage's own new vocabulary: `Repeat`,
`RepeatItem`, `Show`, `Predicate`, `PredicateRef`, `ItemIndexRef`,
`ClassBindSpec`, `ModelBindSpec` were defined in `arklight/api.py`/
`arklight/ast/nodes.py` but missing from both `arklight/api.py`'s own
`__all__` and `arklight/__init__.py`'s import/`__all__` list -- the
same gap `tests/test_package_exports.py` already found and fixed
once before, for the v0.003 second vocabulary addendum. `from
arklight import *` now reaches everything the public API defines.

## Implementation

- `arklight/backend/js/actions/geolocate.py` (already landed in an
  earlier, incomplete pass of this stage) -- the `geolocate` action
  fragment. `arklight/ir/schema.py` -- `ACTION_REGISTRY["geolocate"]`
  (no args). `arklight/api.py` -- `Action.geolocate(name)`.
- `arklight/backend/js/behaviors/paste.py` (new) -- the `paste`
  behavior fragment, mirroring `copy.py`.
  `arklight/backend/js/behaviors/__init__.py` -- registers it into
  `BEHAVIOR_MODULES`. `arklight/ir/schema.py` --
  `BEHAVIOR_REGISTRY["paste"]`.
- `arklight/api.py` -- `State(...)` gains a `media=` parameter.
  `arklight/ir/build.py` -- `IRPage.media: list[tuple[str, str]]`
  (new field) and `_extract_page_state` now also extracts `(name,
  query)` pairs. `arklight/ir/validate.py` -- validates `media` is a
  non-empty string when given. `arklight/backend/html/page_render.py`
  -- emits a `data-ark-media` hydration attribute alongside the
  existing `data-ark-persist` one. `arklight/backend/js/runtime/
  state.py` -- `initState()` reads it, overrides each media key's
  initial value with `matchMedia(...).matches`, and attaches the
  live-updating `"change"` listeners (guarded, like every `window.*`
  access this stage adds, with a `typeof window !== "undefined"`
  check so the same runtime file stays testable from a Node.js
  harness with no real `window` global).
- `arklight/ir/schema.py` -- new `REVEAL_REGISTRY`/
  `KNOWN_REVEAL_BEHAVIORS`, deliberately separate from
  `BEHAVIOR_REGISTRY`/`KNOWN_BEHAVIORS` (see the module's own comment
  for why folding `on_reveal=` into `on_click=`'s registry would be a
  footgun). `arklight/ir/validate.py` -- `_validate_reveal_props`
  (no `behavior_target` requirement, unlike `on_click`).
  `arklight/backend/html/attrs.py` -- compiles `on_reveal=` to
  `data-ark-on-reveal`. `arklight/backend/js/runtime/reveal.py`
  (new) -- `wireReveal()`, registered into `runtime/__init__.py` and
  shipped/called from `arkInitPage()` in `arklight/backend/js/
  render.py` only when `on_reveal=` is used anywhere on the site,
  independent of `has_state`.
- `Bind.model(..., debounce=..., throttle=...)`/`ModelBindSpec`
  (already landed in an earlier, incomplete pass of this stage) --
  `arklight/ast/nodes.py`, `arklight/api.py`,
  `arklight/backend/html/attrs.py` (`data-ark-model-modifiers`).
- `arklight/api.py`, `arklight/__init__.py` -- `__all__`/import-list
  fixes described above.

No changes to `arklight/ir/normalize.py`.

## Tests

`tests/test_js_vocabulary_v0063.py` (new, 36 tests) -- `Action.
geolocate`/`ACTION_REGISTRY` coverage and validation against
undeclared state; `paste`'s `BEHAVIOR_REGISTRY`/`BEHAVIOR_MODULES`
coverage, `behavior_target` requirement, and HTML/JS output;
`State(..., media=...)` round-tripping through the IR, validation of
non-string/empty `media`, and HTML/JS output; `on_reveal=` validation
(including that it does *not* require `behavior_target`, unlike
`on_click`) and HTML/JS output, and that `has_reveal` ships/calls
`wireReveal()` independent of `has_state`; `Bind.model(...,
debounce=...)`/`.throttle(...)` return-value and HTML attribute
checks; a combined test exercising all five primitives on one page;
regression tests that `from arklight import *` and `from arklight.api
import *` both reach every previously-missing name; and a Node.js
check of the shipped `wireReveal` fragment's default toggle-class
literal. Full suite: 1204 passed (2 pre-existing, unrelated
`test_version.py` failures in this sandbox from `arklight` not being
`pip install`ed -- present on `main` before this stage too), no
regressions.
