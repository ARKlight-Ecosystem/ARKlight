# v0.0035 -- Stateful JS

Adds a real, structured capability for page-scoped reactive state --
deliberately capability, not vocabulary: no new named behaviors, just
the registry refactor plus the primitives everything after this
version builds on.

## What shipped

- New public API: `State(name, initial)` for page-scoped reactive
  state, `Bind(name)` to reference declared state anywhere a literal
  prop value is accepted (e.g. `Text(Bind("count"))`), and
  `Action.set` / `Action.increment` / `Action.toggle_bool` for
  `on_click=`.
- `BEHAVIOR_REGISTRY` and `ACTION_REGISTRY` replace the old flat
  `KNOWN_BEHAVIORS` set as the source of truth -- the JS runtime is
  now assembled from small per-behavior/per-action fragments, and
  only the fragments a given site actually uses are shipped.
- Validation: every `Bind(...)` / `Action.*(...)` must reference a
  `State(...)` actually declared on that page, or the build fails at
  compile time with a specific message.
- Pages that declare state get a small, fixed reactive core appended
  to the runtime; pages without it get none of it. Still no `eval`,
  no `new Function`, no string ever executed as code.
