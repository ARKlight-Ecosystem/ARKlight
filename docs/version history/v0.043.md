# v0.043 -- Optional `<head>` metadata + backend postprocess hook

Two small, additive extension points: a structured way to fill in a
page's `<head>` beyond the charset/viewport/title/stylesheet lines
every page already got, and a general-purpose hook for a backend to
transform combined output after every backend has rendered.

## What shipped

- **Optional `<head>` metadata props on `Page(...)`** --
  `description`, `favicon`, `og_title`, `og_description`, `og_image`,
  plus free-form `meta`/`links` -- read and rendered by
  `_render_head_meta` (`arklight/backend/html/head_meta.py`). All are
  optional: omitting every one of them leaves a page's generated
  `<head>` byte-for-byte unchanged.
  - `favicon`/`og_image` are root-relative asset paths, resolved the
    same way `page_render.py` already resolves stylesheet/script
    paths (a leading `/` is stripped before resolution).
  - Open Graph tags are fully opt-in: they only appear once
    `description` or any `og_*` prop is supplied. `og_title`/
    `og_description` fall back to `title`/`description` when not set
    explicitly.
  - `meta`/`links` cover anything else (webfonts, preconnect, extra
    icons) and are emitted verbatim -- unlike `favicon`/`og_image`,
    these are not run through asset-path resolution.
- **`Backend.postprocess(output_files)`** (`arklight/backend/base.py`)
  -- an optional second pass over the *combined* output of every
  backend's `render()`, run in `backends=[...]` order after all
  `render()` calls finish. Default is a no-op identity, so
  `HTMLBackend`/`CSSBackend`/`JSBackend` needed no changes. Intended
  as the preferred extension point for a new backend that needs to
  add or transform files depending on what other backends already
  produced, rather than editing an existing backend's `render()`
  directly.

For the module-level design context, see
[`docs/Foundational/DESIGN-NOTES.md`](../Foundational/DESIGN-NOTES.md)
and `arklight/backend/html/head_meta.py`'s module docstring.
