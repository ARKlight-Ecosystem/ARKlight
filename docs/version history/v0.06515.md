# v0.06515 -- `arklight deploy`: deploy a built site with Wrangler

A new subcommand, out-of-band (numbered inside the `v0.065` range, like the
other `0.0650x` increments). It builds your site and hands the result to
[Wrangler](https://developers.cloudflare.com/workers/wrangler/), Cloudflare's
own CLI, to publish on Cloudflare Workers. ARKlight does not deploy anything
itself.

```bash
arklight deploy                      # same as: arklight deploy cloudflare
arklight deploy cloudflare my_site.py -o public --name my-portfolio
arklight deploy --dry-run            # build, then print the command instead of running it
arklight deploy --skip-build         # deploy the existing ARK/ as it is
```

- **Needs Wrangler installed and signed in first.** ARKlight never installs
  it. If `wrangler` isn't on your `PATH`, `deploy` builds the site, says so,
  and stops with the install steps (`npm install --global wrangler`,
  `wrangler login`).
- **No Wrangler config in your project:** ARKlight runs
  `wrangler deploy --assets <build dir> --name <name> --compatibility-date <today>`.
  The name is `--name`, or your project folder's name in lowercase.
- **A `wrangler.jsonc`/`.json`/`.toml` next to your site file:** ARKlight runs
  a plain `wrangler deploy` and your config decides what goes out. It does not
  check that the config points at the folder it just built.
- **Wrangler's output is shown as-is** (sign-in prompts, progress, the
  deployed URL), and its exit code is `arklight deploy`'s exit code, so CI sees
  Wrangler's result directly.
- A failed build stops the run before Wrangler starts.

Cloudflare Workers is the only provider so far. Other providers, a `deploy`
section in `arklight.config.py`, and Cloudflare Pages are not built. Alpha-only:
not yet on `main`. Full reference: `docs/Foundational/CLI-REFERENCE.md`; the
design and what was deliberately left out: `docs/Foundational/DEPLOYMENT-CLI.md`.
