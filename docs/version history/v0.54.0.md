# v0.54.0 -- Alpha catch-up: CSS media queries, HTML backend refactor, reactive JS core, search engine, live-streaming/CCTV

The first release on the new `MAJOR.MINOR.PATCH` version format (see
"Version numbering" below). Brings `main` up to parity with `alpha`'s
Stages 1-7 -- Android excluded throughout, verified separately as
part of this release.

## CSS: `@media` queries + structured `<head>`/`<header>` extension

The long-planned [v0.048](../Foundational/DESIGN-NOTES.md) milestone,
now shipped:

- `Site.media_query(condition, class_name, rules)` (experimental,
  gated under `css-media-queries` in `docs/EXPERIMENTAL-APIS.md`) and
  per-node media conditions, both rendered as real
  `@media (condition) { .class_name { ... } }` blocks -- an explicit,
  opt-in escape hatch on top of the intrinsic-design layout classes
  (`.stack`, `.switcher`, `.grid`, ...), which stay the default. See
  the README's "Responsive layout" section.
- `@keyframes`, `@font-face`, container queries, `@supports`, `@page`,
  and `@import` rendering, plus arbitrary selector-based rules via
  `Site.style_selector(...)`.

## HTML backend refactor

Pure internal extraction (attrs / head+meta / page render / routing /
tag map split into their own modules) -- no behavior change, but each
piece is now independently testable.

## Reactive JS core

- Computed/derived state and `Watch(...)` effects.
- Two-way input binding (`bind_value=`).
- Per-item list rendering (`Repeat`) and conditional show/hide
  (`Show`).
- Event modifiers.
- `localStorage` persistence via `State(..., persist=True)`.

## Search engine

`arklight search` -- a new CLI subcommand backed by a standalone
search/ranking/retrieval subsystem.

## Live-streaming dev server, CCTV, `--upgrade-alpha`

- `arklight live-streaming` -- auto-rebuild + browser auto-reload on
  file change.
- `arklight/cli/cctv.py` tooling.
- `arklight --upgrade-alpha` -- switches a git-checkout install over
  to the `alpha` branch in place.

## Version numbering

From this release on, versions are `MAJOR.MINOR.PATCH` rather than
the old `0.0NN`-as-decimal-fraction milestone numbers used through
[v0.041](./v0.041.md) -- the old scheme is a real
[PEP 440](https://peps.python.org/pep-0440/) hazard (`0.100`
normalizes to `0.1`, sorting *below* `0.048`'s `0.48`), and PyPI's own
version-comparison rules made the old milestone bookkeeping
unworkable going forward.

For the full technical entry (exact files touched per subsystem, and
the Stage 8 Android-exclusion / Stage 9 verification results), see the
root [`CHANGELOG.md`](../../CHANGELOG.md).
