# v0.061 -- JS vocabulary: math siblings

First rung of the JS vocabulary expansion (see
[`docs/Proposals/JS-VOCABULARY-EXPANSION-PROPOSAL.md`](../Proposals/JS-VOCABULARY-EXPANSION-PROPOSAL.md)
for the full catalog this ladder works through, and
[`docs/Implementation/JS-VOCABULARY-ADDENDUM-v0.070.md`](../Implementation/JS-VOCABULARY-ADDENDUM-v0.070.md)
stage 1 of 10 for the staging plan) -- the cheapest possible
additions, siblings of derivations that already exist.

## What shipped

- `Derive.subtract`, `Derive.divide`, `Derive.min`, `Derive.max` --
  the missing siblings of `Derive.sum`/`Derive.multiply`, same
  `DERIVATION_REGISTRY` shape, no new IR node. `subtract`/`divide`
  aren't associative like `sum`/`multiply`, so each needs at least
  two names: `names[0]` is the starting value, and every later name
  applies against it in declared order (`Derive.subtract("total",
  "discount")` reads as `total - discount`). `min`/`max` are
  associative like `sum`, so one name is already meaningful.
- `divide` mirrors JavaScript's own `x / 0` float semantics
  (`Infinity`/`-Infinity`/`NaN`, never a thrown error) on the Python
  build-time evaluation side too, rather than letting Python's `/`
  raise `ZeroDivisionError` -- keeps the server-rendered `Bind(...)`
  text and the client recompute in agreement even at this edge case.

```python
Computed("net", deps=("total", "discount"), derive=Derive.subtract("total", "discount"))
Computed("share", deps=("total", "count"), derive=Derive.divide("total", "count"))
Computed("lowest", deps=("a", "b", "c"), derive=Derive.min("a", "b", "c"))
Computed("highest", deps=("a", "b", "c"), derive=Derive.max("a", "b", "c"))
```

No changes to `arklight/ir/validate.py`'s validation *logic* (the
existing `DerivationSpec`-driven arity check already covers the new
`min_names`/`max_names` values), `arklight/ir/normalize.py`, or any
backend beyond the four new fragment files -- a `Computed(...)` using
one of these is indistinguishable, structurally, from one using
`sum`/`multiply`.
