# v0.041 -- CLI, pipeline & JS runtime hardening + stateful JS vocabulary addenda

Four change sets landed together and shipped as one version: two
error-handling hardening passes (CLI/pipeline, then the generated
client-side runtime) and two growth passes on the stateful-JS action
vocabulary introduced in [v0.0035](./v0.0035.md).

## Stateful JS vocabulary addendum I

- `Action.decrement(name, delta=1)` -- the `-1` counterpart to
  `Action.increment`.
- `Action.reset(name)` -- resets a state key back to its declared
  `State(...)` value.

## Stateful JS vocabulary addendum II

- `Action.append(name, value)` / `Action.remove(name, index)` -- the
  first actions to assume a list-valued `State(...)` rather than a
  scalar one.

## CLI & pipeline error-handling hardening

- A top-level catch-all in the CLI's `main()`, so anything outside a
  subcommand's own anticipated failure modes gets a clear message
  instead of a raw Python traceback.
- Filesystem-failure guards around the build's file-write and asset
  copy steps, reporting exactly how much of the build completed
  before a failure.
- A visible runtime warning when `--passphrase` is passed on the
  command line (shell history / process-listing exposure).

## JS runtime error-handling hardening

- `arkNotify(message)` -- a small on-page notice so end users get a
  visible signal when the runtime hits something unexpected, instead
  of a console-only error nobody but a developer would see.
- `try`/`catch` around state initialization and around each
  element's action/behavior wiring individually, so one malformed
  attribute (or one behavior throwing at click time) can no longer
  take the rest of the page's interactivity down with it.
- A `.catch()` on the `copy` behavior's clipboard promise, notable
  because `arklight build --open` opens sites as `file://` URLs by
  default -- exactly where clipboard permissions are likeliest to be
  denied.
