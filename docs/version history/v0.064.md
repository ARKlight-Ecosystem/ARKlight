## What shipped: `arklight search --retrieve-doc`

A new mode on the existing `arklight search` subcommand that switches
it from component-schema lookup into doc-tree retrieval -- read-only
and unsynthesized: exact, unmodified file bytes from `docs/`, nothing
invented or summarized.

```bash
arklight search --retrieve-doc
arklight search --retrieve-doc --foundational
arklight search --retrieve-doc --foundational --file architecture
```

- Bare `--retrieve-doc` (or the literal `index` in place of a
  component name) prints the root `docs/README.md`, plus a footer
  listing every folder flag below.
- A folder flag -- `--foundational`, `--backends`, `--proposals`,
  `--implementation`, `--js-backend` (removed later, along with its folder), `--far-future`,
  `--version-history`, one per `docs/README.md`'s own Folder Guide --
  prints that folder's own `README.md` index, plus a footer listing
  the files available inside it.
- `--file NAME`, scoped to a preceding folder flag, appends that
  file's full contents after the folder index. Matched
  case-insensitively by filename stem, with spaces/hyphens/underscores
  normalized (`--file architecture`, `--file Architecture`, and
  `--file ARCHITECTURE` all resolve to `ARCHITECTURE.md`); an
  unmatched name gets a typo-tolerant "did you mean" list, the same
  posture as component lookup's own suggestions. `--file` without a
  preceding folder flag is a hard error naming the folder the file
  actually lives in, if one matches.
- Mutually exclusive with a component `name` lookup and with
  `--serve`; `--limit`/`--near`/`--accept` are component-lookup-only
  and are ignored (with a notice) alongside `--retrieve-doc`.
- Only works from an ARKlight source checkout -- `docs/` isn't
  packaged into the installed wheel, so this fails loudly with a
  clear error rather than pretending to have something to show when
  run against an installed package.

## Implementation

- `arklight/cli/doc_retrieval.py` (new) -- the retrieval logic itself:
  the seven-entry `DOC_FOLDERS` table (one per `docs/README.md`
  lifecycle folder), root/folder-index printing, `--file` stem
  matching with a `difflib`-based "did you mean" fallback, and
  `DocRetrievalError` for the installed-package/missing-file cases.
- `arklight/cli/main.py` -- wires `--retrieve-doc`, the seven folder
  flags, and `--file` onto the existing `search` subparser; dispatches
  into `doc_retrieval.py` before falling through to ordinary
  component-schema lookup.
- `arklight/cli/search.py` -- no logic changes; `--retrieve-doc`
  short-circuits before this module's component-lookup path runs.

# What shipped: the math derivations catalog (JS vocabulary stage 4/10)

Twenty-one new `Derive.*` kinds for `Computed(...)`, the same
one-fragment-plus-one-registry-line shape as `sum`/`multiply` -- no new IR
node. Inputs are read the way `sum` reads them (`Number(x) || 0`, so a
missing or non-numeric value counts as `0`); results follow JavaScript's own
`Math.*`, so an out-of-domain input gives `NaN`/`Infinity` rather than a
build or runtime error.

| Group | Kinds | Names |
|---|---|---|
| Rounding / sign | `absolute`, `ceiling`, `floor`, `truncate_number`, `sign` | one |
| Roots / powers / logs | `sqrt`, `cbrt`, `exp`, `log`, `log2`, `log10` | one |
| | `power(base, exponent)` | two, in order |
| Aggregates | `hypot`, `average` (alias `mean`), `median`, `gcd`, `lcm` | one or more |
| Ratios | `percentage_of(part, whole)` -- `(part / whole) * 100` | two, in order |
| Bounds | `clamp(value, low, high)` -- `min(max(value, low), high)` | three, in order |
| Display strings | `to_fixed(name, digits)`, `to_precision(name, digits)` | one, plus `digits` |

```python
Computed("share", deps=("done", "total"), derive=Derive.percentage_of("done", "total"))
Computed("price_text", deps=("price",), derive=Derive.to_fixed("price", 2))   # "9.50"
Computed("shown", deps=("qty", "lo", "hi"), derive=Derive.clamp("qty", "lo", "hi"))
Computed("distance", deps=("dx", "dy"), derive=Derive.hypot("dx", "dy"))
Computed("typical", deps=("a", "b", "c"), derive=Derive.median("a", "b", "c"))
```

- `gcd`/`lcm` truncate each value to a whole number and take its absolute
  value first; `gcd(0, 0)` is `0`, `lcm` with any `0` is `0`.
- `clamp` with `low` above `high` returns `high` (it is exactly
  `min(max(value, low), high)`).
- `to_fixed`/`to_precision` return a **string**, meant for display -- a
  string is not further arithmetic input. `digits` is a literal integer,
  range-checked at build time to what JavaScript accepts (`0`-`100` and
  `1`-`100`); anything else is a build error, not a browser `RangeError`.
  Like JavaScript, an exact tie rounds away from zero: `to_fixed(2.5, 0)` is
  `"3"`, while `1.005` at two digits is `"1.00"` because the double is really
  `1.00499999...`.
- `random_int` is not part of this stage; it stays with `v0.070`'s design
  exception.

**Known limit.** `exp`, `log`, `log2`, `log10`, `cbrt`, `power` and `hypot`
are computed by each platform's math library -- the build machine's at build
time, the browser's when the client recomputes -- so the pre-rendered value
can differ from the recomputed one in the final binary digit
(`hypot(2, 3)` is `3.605551275463989` at build time and
`3.6055512754639896` in V8). Everything else in the catalog is bit-identical.
Format with `Derive.to_fixed` for anything the reader sees; `cbrt` is at
least made exact for perfect cubes (`cbrt(27)` is `3`).

Fixed along the way, all toward the invariant that server-rendered `Bind`
text agrees with the client recompute: a `Computed(...)` reading a
`NaN`-valued `Computed(...)` now reads `0` at build time as it does in the
browser; `Derive.sum` sums left to right instead of using Python 3.12's
compensated `sum()`; and a non-finite result is pre-filled as
`NaN`/`Infinity`/`-Infinity`, not `nan`/`inf`.

## Implementation

- `arklight/backend/js/derivations/<kind>.py` (21 new) -- each `NAME` +
  `JS_FRAGMENT`, registered in `derivations/__init__.py`.
- `arklight/ir/schema.py` -- 21 `DERIVATION_REGISTRY` entries, plus
  `DIGITS_RANGES`.
- `arklight/ir/js_numeric.py` (new) -- the build-time mirrors of `Math.*`/
  `toFixed`/`toPrecision`, where Python's `math` raises or rounds
  differently.
- `arklight/ir/build.py` -- the new cases in `_evaluate_derivation`, and the
  `_coerce_number`/`sum` parity fixes.
- `arklight/ir/validate.py` -- the `digits` range check.
- `arklight/api.py` -- the `Derive.*` constructors.
- `arklight/backend/html/page_render.py` -- non-finite `Bind(...)` pre-fill.
