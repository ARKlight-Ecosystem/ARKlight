## `Provider`, stage 2 of 6: IR and validation integration (SHIPPED)

Threads a declared `Provider` through the compiler pipeline the same
way `site.media_query(...)` already threads its own experimental
config through `WebsiteIR`.

### What shipped

- **`WebsiteIR.provider: ProviderDeclaration | None`**
  (`arklight/ir/build.py`) -- a straight passthrough of
  `Site(provider=...)`, same shape as `media_queries`/`app_shell`.
  `build_website_ir(...)` gained a matching `provider=` keyword
  argument. `arklight/compiler/pipeline.py` now passes
  `provider=site.provider` through, so `ir.provider` carries the
  actual `ProviderDeclaration`, not just its recorded experimental
  usage (which `0.06514` already threaded via `experimental_usages`).
  Still nothing reads this field downstream -- a build with a
  `Provider` stays byte-identical to one without, apart from the
  reports every gated experimental feature already gets (unchanged
  from stage 1).
- **`arklight/ir/validate.py`'s `validate_provider(provider)`** -- the
  closed capability vocabulary
  (`arklight.provider.PROVIDER_CAPABILITIES`) is now enforced at the
  pipeline's own "Running validation..." stage, alongside
  `validate_ark_ast`, raising this module's shared `ValidationError`
  rather than `ProviderDeclaration`'s own `ValueError`. In ordinary
  use `Provider.declare(...)`/`ProviderDeclaration.__post_init__`
  already reject an invalid declaration before it can reach
  `Site(provider=...)`, so this check is defense in depth -- the
  officially designated validation stage independently re-confirming
  a value built elsewhere in the pipeline, the same discipline every
  other schema check in that module already follows, rather than a
  new kind of trust in the object that produced it. `Site(provider=...)`
  isn't a node in the ARK AST tree, so this is a direct function call
  from `pipeline.build`, not part of `validate_ark_ast`'s tree walk.
- The `.arklight` binary format's known-gap comment
  (`arklight/ir/binary.py`) now lists `provider` alongside
  `media_queries`/`raw_postprocessors`/etc. -- not yet round-tripped,
  same as those.
- `tests/test_provider.py` gained 8 new tests (47 -> 55) covering
  `validate_provider`'s no-op/error paths and confirming `ir.provider`
  carries the real declaration; full suite 2170 passed.
