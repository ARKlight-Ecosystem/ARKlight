# v0.054 -- JS backend capability expansion (reactive core)

ARKlight's reactive core reaches parity with the kind of thing Vue 3's
Composition API gives you -- computed state, watch effects, two-way
binding, per-item list rendering, conditional show/hide, event
modifiers, and reactive class binding -- all still compiled from a
closed, described vocabulary. No arbitrary JS/`eval` anywhere; the
browser never executes anything ARKlight itself didn't generate from a
known, validated shape.

Landed as 8 separate staged sub-releases (`vdom-1` through `vdom-8`),
rolled up here into one milestone-level summary -- see `PROGRESS.md`'s
Snapshot table if you want the individual per-stage record.

## What shipped

- A vendored `snabbdom` bare core swapped into `State`'s re-render pass
  (`vdom-1`).
- Reactive class binding -- `Bind.when(...)`/`bind_class=` (`vdom-2`).
- Event modifiers -- `.with_modifiers(...)`/`.debounce(...)`/
  `.throttle(...)` (`vdom-3`).
- Computed/derived state -- `Computed(...)`/`Derive.*` (`vdom-4`).
- Watch effects -- `Watch(...)` (`vdom-5`).
- Two-way input binding -- `bind_value=Bind.model(...)` (`vdom-6`).
- Per-item list rendering (`Repeat`) + conditional show/hide (`Show`)
  (`vdom-7`).
- `localStorage` persistence for `State(..., persist=True)` (`vdom-8`).
