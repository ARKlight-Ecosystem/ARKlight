## JS vocabulary, stage 7 of 10

Seventh rung -- reduces a list-typed `State` value to a scalar the
way `sum`/`count` already reduce multiple *named* states. Still
scalar-out, so it fits today's `DERIVATION_REGISTRY` as-is; the
list-in/list-out sort/filter registry these read like siblings of
stays out of scope for this ladder (Tier 3, still an open proposal).

### What's planned

- `list_length`, `list_min`, `list_max`, `list_average`,
  `list_first`, `list_last`, `list_includes`, `list_any`, `list_all`

## `Provider`, stage 3 of 6: JS backend emission

Emits the fixed, minimal config a validated `Provider` declaration
needs at runtime -- no network call, no vendor SDK, no generated glue
that actually talks to anything.

### What's planned

- A small config blob (mirroring how `data-ark-state` carries
  `State(...)`'s baked initial values) describing which capabilities
  a page uses and what DOM hooks/state keys they're wired to.
- Zero output for a build that never declares a `Provider` -- same
  "only ship what's used" discipline the JS backend already applies
  elsewhere.
