# v0.0641 -- Emergency patch: URL query-parameter state

A small, out-of-band patch between `v0.064` and `v0.065`, same
treatment as `v0.0431`: `State(name, initial, query="page",
history="push")` -- ARKlight's first authored primitive for reading,
writing, and reacting to URL query parameters (`?page=2`,
`?sort=price`), extending the existing `persist=`/`media=` two-way
sync model rather than inventing a new one.

```python
State("page", 1, query="page", history="push")
Text(Bind("page"))
Button("Next", on_click=Action.increment("page", 1))
```

- `query="page"` keeps this state key synced with the `?page=`
  query-string parameter: reads it (with type coercion) on load, keeps
  it live across browser back/forward navigation, and writes it back
  via `history.replaceState`/`pushState` on every change.
- `history="push"` (opt-in; `"replace"` is the default) gives that
  key's changes a real, back-button-worthy history entry.
- Never triggers a page reload or a document re-fetch -- this stays a
  synchronous, in-memory update, the same as every other reactive
  primitive in ARKlight.

Accepted as an emergency patch, not deferred to a later numbered
milestone: capability gaps that block real use of the compiler --
same category as `v0.0431`'s bug-fix patch, and treated with at least
the same priority -- get addressed where the work is, rather than
queued behind whatever numbered milestone happens to be in flight.
